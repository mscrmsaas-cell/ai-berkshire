## 2. 数据流图

### 2.1 实时检测流程 (眼镜 → 挎包终端 → 眼镜)

```
[眼镜 OV2640 捕获 JPEG]
        │
        ▼  MSG_CAMERA_FRAME (0x20, 分包)
[BLE NUS 传输]
        │
        ▼
[挎包终端 BLE 网桥接收]
        │
        ├──→ [图像预处理: 解码→resize 320×320→归一化→NCHW]
        │
        ▼
[YOLOv8n ONNX 推理]
        │
        ▼
[后处理: NMS→坐标映射→置信度过滤]
        │
        ├──→ [SQLite ai_detection_cache 缓存]
        │
        ▼  MSG_DETECT_RESULT (0x23)
[BLE NUS 传输]
        │
        ▼
[眼镜 LVGL 渲染 AR 标注框]
```

### 2.2 RAG 问答流程 (眼镜语音 → 挎包终端 → 眼镜)

```
[眼镜 INMP441 采集语音]
        │
        ▼  MSG_AUDIO_CHUNK (0x30)
[BLE 传输]
        │
        ▼
[挎包终端 ASR → 文本]
        │
        ▼  MSG_RAG_QUERY (0x40)
[本地 RAG 引擎]
        │
        ├──→ [BGE-small-zh 向量化]
        │
        ├──→ [Qdrant Top-5 检索]
        │
        ├──→ [组装 Prompt]
        │
        ▼
[Phi-3-mini 生成回答 (≤512 tokens)]
        │
        ▼  MSG_RAG_ANSWER (0x41)
[BLE 传输]
        │
        ▼
[眼镜 LVGL 显示回答]
        │
        ▼  MSG_TTS_AUDIO (0x33)
[眼镜 MAX98357A 播放语音]
```

### 2.3 离线数据同步流程 (挎包终端 → SaaS)

```
[网络恢复检测]
        │
        ▼
[按优先级查询 sync_state: P0 告警 → P1 照片 → P2 检测 → P3 RAG → P4 遥测]
        │
        ▼
[批量同步 (指数退避重试)]
        │
        ├──→ POST /api/v1/inspections/{id}/alerts      (P0)
        ├──→ POST /api/v1/uploads/photo                 (P1)
        ├──→ POST /api/v1/inspections/{id}/detections   (P2)
        ├──→ POST /api/v1/rag/sync                      (P3)
        └──→ POST /api/v1/telemetry/batch                (P4)
        │
        ▼
[更新 sync_state: synced / failed]
```

## 3. 通信拓扑

### 3.1 连接关系

| 源 → 目标 | 介质 | 协议 | 方向 |
|----------|------|------|------|
| 眼镜 → 挎包终端 | BLE | NUS GATT (从→主) | 双向 |
| 眼镜 → 涂鸦云 | BLE | 涂鸦 BLE SDK | 上报 |
| 挎包终端 → 涂鸦云 | WiFi/5G | MQTT (涂鸦 Linux SDK) | 双向 |
| 挎包终端 → SaaS | 5G/4G | HTTPS REST API | 双向 |
| 摄像模块 → 眼镜 | Pogo Pin | DVP 并行 + SCCB | 单向 (数据) |

### 3.2 BLE 拓扑

```
                    挹包终端 (Central)
                   /        |          \
              眼镜1      眼镜2       眼镜3   眼镜4
           (Peripheral) (Peripheral)  ...   (最多 4 副并发)
```

- 每副眼镜同时仅连接 1 个 Central (GAP max_conn = 1)。
- 挎包终端 Bleak 同时管理最多 4 个 Peripheral 连接。
- 每个连接独立维护 NUS 帧序列号 (SEQ) 和 ACK 状态。

### 3.3 涂鸦云拓扑

```
涂鸦 IoT 云平台
    │
    ├── MQTT ── 挎包终端 (涂鸦网关, Linux SDK)
    │              │
    │              ├── 子设备注册: 眼镜1/2/3/4
    │              └── DP 代理: 上行 10 个 + 下行 4 个
    │
    └── BLE ── 眼镜 (涂鸦 BLE SDK, 备用直连)
```

- 涂鸦集成可选 (编译时 `CONFIG_TUYA_ENABLE` 开关)。
- 未启用时，眼镜仅通过 BLE NUS + REST API 通信。

## 4. 电源管理策略

| 场景 | 眼镜状态 | CPU 频率 | 背光 | 说明 |
|------|---------|---------|------|------|
| 巡检中 | 全功能 | 240MHz | 100% | BLE 连接 + 显示 + 摄像 |
| 待机 | 低功耗 | 80MHz | 30% | 30 秒无操作进入 |
| 充电中 | 全功能 | 240MHz | 100% | 充电时允许巡检 |
| 低电量 (<15%) | 降频 | 160MHz | 50% | 关闭摄像头，仅保留 BLE |
| 深度睡眠 | 极低功耗 | 10MHz | 0% | BLE 唤醒 / GPIO 唤醒 / 定时唤醒 |

## 5. 关键设计决策

1. **ESP32-S3 替代 Android** — 开源生态成熟、成本极低 ($5 级)、ESP-IDF + LVGL 足够驱动 240×240 LCD 和 I2S 音频。
2. **OV2640 直连无需独立 MCU** — 通过 Pogo Pin 接入 ESP32-S3 DVP 接口，降低成本和复杂度。
3. **CM4 作为挎包终端** — 性能/功耗/生态平衡点，可选配 Hailo-8L 加速器。
4. **Bleak 作为 Python BLE 库** — 跨平台、API 清晰、支持 BlueZ D-Bus。
5. **ONNX Runtime 而非 PyTorch** — 推理专用、ARM NEON 优化好、支持 Hailo 后端。
6. **Qdrant 本地模式而非 Milvus** — 单进程本地模式更轻量，适合终端资源限制。
7. **Phi-3-mini Q4 量化** — 约 2GB 内存占用，CM4 可承载，推理 2-5 秒可接受。
8. **涂鸦集成可选** — 编译时配置开关，不启用时直接 BLE + REST 通信。
9. **SaaS 扩展文件放 Monorepo** — 保持 Monorepo 自包含，部署时手动复制。
10. **模型文件不入仓库** — .onnx/.gguf 通过 .gitignore 排除，download_models.sh 从 MinIO 拉取。
