一、眼镜与挎包通信方案 (BLE 1:1)

通信方式选型：BLE 5.0 LE Secure Connections

选型维度BLE 5.0WiFi DirectLoRaUWB
通信距离可控 (TX 功率调节)30-100m (不可控)1-15km (过长)10-30m
1:1 配对原生支持需额外配置广播模式支持
功耗极低高低中
抗干扰自适应跳频 (79 信道)固定信道窄带超宽带
加密AES-128 (LE SC)WPA3AES-128AES-128
铁路频段合规2.4GHz ISM (免许可)2.4/5GHz需许可6-8GHz
实时性<100ms<50ms1-10s<10ms
带宽1-2 Mbps (MTU 247B)54-433 Mbps0.3-50 kbps0.5-1 Mbps

选型结论：BLE 5.0 LE Secure Connections

1. 通信距离可通过 TX 功率精确控制到 10 米以内
2. 自适应跳频扩频 (AFH) 抗铁路电磁干扰（牵引回流、接触网电弧）
3. 2.4GHz ISM 频段免许可，无需向铁路无委申请频率
4. 功耗极低，适合眼镜端电池供电
5. LE Secure Connections 提供 AES-128 加密配对（ECDH 密钥交换）

BLE 安全配置

参数配置值说明
max_connections1严格 1:1，仅允许一副眼镜
tx_power_dbm-6控制通信距离 ≤10m（铁路金属环境衰减更快）
pairing_modele_secureLE Secure Connections (ECDH 密钥交换)
encryption_key_size16AES-128 加密
bonded_device_address预绑定 MAC仅允许预绑定的眼镜连接
rssi_disconnect_threshold-85 dBm低于此值主动断连，防止远距离窃听
heartbeat_interval5s缩短心跳，快速检测异常断连
heartbeat_timeout15s超时自动断开重连

铁路频段合规说明

  • BLE 使用 2.4GHz ISM 频段 (2400-2483.5MHz)，全球免许可使用
  • 中国铁路沿线无线通信主要限制在 GSM-R (900MHz) 和 LTE-R (1.8GHz) 专用频段
  • BLE 的 2.4GHz 与铁路专用通信系统频段不重叠，无干扰风险
  • 自适应跳频 (AFH) 自动避开被占用的信道，进一步降低干扰

二、挎包与指定 PC/服务器的有线连接

连接方式

特性配置
物理接口USB 2.0 Type-C (CM4 OTG)
网络模式CDC-ECM (USB 网卡)

串口调试CDC-ACM /dev/ttyACM0
隔离方式iptables 双向 DROP (USB ↔ 其他接口)

数据传输方式

方式 A：.dat 打包文件传输

挎包终端将数据打包为 .dat 二进制容器文件，PC 通过 USB 拷贝后用专业应用导入。这是主要方式。

方式 B：API 接口调用（后续开发）

PC 端专业应用通过 HTTP API 直接访问挎包数据（仅 USB 局域网 10.0.0.x）。

.dat 文件格式

┌────────────────────────────────────────────────────┐
│ Header (64B)                                        │
│  Magic "RAIL" + Version 2 + 段偏移/大小             │
├────────────────────────────────────────────────────┤
│ Data 段                                             │
│  [PathLen][Path][FileSize][SHA256][Content] × N    │
├────────────────────────────────────────────────────┤
│ Manifest 段 (JSON)                                  │
│  导出ID + 类型 + 文件列表 + 元数据                  │
├────────────────────────────────────────────────────┤
│ Signature 段 (64B)                                  │
│  HMAC-SHA256 (hex)                                  │
└────────────────────────────────────────────────────┘

方式 A：.dat 传输流程

挎包端:  收集数据 → 计算 SHA-256 → 生成 manifest →
         HMAC-SHA256 签名 → 封装为 .dat → 存入 /exports/

PC 端:   USB 连接 → 挂载 → 拷贝 .dat → 专业应用导入 →
         验证 HMAC 签名 → 逐文件校验 SHA-256 → 解析数据

PC/服务器端 Docker Compose 部署

# pc-server/docker-compose.yml
version: "3.8"

services:
  # PostgreSQL 数据仓库
  postgres:
    image: postgres:15
    environment:
      POSTGRES_DB: railway_inspection
      POSTGRES_USER: rail
      POSTGRES_PASSWORD: ${PG_PASSWORD}
    volumes:
      - pg-data:/var/lib/postgresql/data
    ports:
      - "127.0.0.1:5432:5432"

  # Qdrant 全量向量数据库
  qdrant:
    image: qdrant/qdrant:latest
    volumes:
      - qdrant-data:/qdrant/storage
    ports:
      - "127.0.0.1:6333:6333"

  # Dify RAG 知识库
  dify:
    image: langgenius/dify-api:latest
    environment:
      DB_PASSWORD: ${PG_PASSWORD}
      QDRANT_URL: http://qdrant:6333
    ports:
      - "127.0.0.1:5001:5001"
    depends_on: [postgres, qdrant]

  # YOLOv8x GPU 推理服务
  yolo-server:
    build: ./yolo-server
    runtime: nvidia
    environment:
      NVIDIA_VISIBLE_DEVICES: all
      MODEL_PATH: /models/yolov8x_railway.onnx
    ports:
      - "127.0.0.1:8080:8080"

  # .dat 导入服务 (专业应用后端)
  dat-importer:
    build: ./dat-importer
    environment:
      PG_HOST: postgres
      QDRANT_URL: http://qdrant:6333
      HMAC_KEY: ${BAG_EXPORT_HMAC_KEY}
    ports:
      - "127.0.0.1:9091:9091"
    depends_on: [postgres, qdrant]

volumes:
  pg-data:
  qdrant-data:

六、完整工作流程

日常巡检流程

1
巡检人员佩戴眼镜 + 挎包开机
2
BLE 自动配对 (1:1, 预绑定 MAC, AES-128 加密)
3
眼镜 OLED 显示 "已连接"
4
巡检中：语音 "拍照" → 挎包触发拍照 → YOLOv8n 实时检测 → 结果回显
5
巡检中：语音 "规程查询" → Phi-3 离线 RAG → 答案回显
6
检测到缺陷 → 告警 BLE 推送 → 眼镜振动 + 显示
7
巡检结束 → 数据存入 SQLite + SD 卡

数据导出与分析流程

8
返回指定场所 → USB 数据线连接 PC
9
挎包 OLED 显示 Token → PC 专业应用输入 Token 认证
10
选择导出方式：打包 .dat → PC 拷贝 → 导入验证 (或 API 调用，后续开发)
11
PC/服务器进行：YOLOv8x 精检 → GPT-4V 多模态分析 → Qwen-72B 生成报告 → Dify RAG 关联案例 → PostgreSQL 入库
12
USB 断开 → Token 自动撤销 → 挎包返回待机
