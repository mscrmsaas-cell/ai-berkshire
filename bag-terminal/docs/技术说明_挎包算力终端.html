一、大模型选型

挎包终端采用 Microsoft Phi-3-mini-4k-instruct (Q4 量化 GGUF) 作为核心大语言模型，配合 BGE-small-zh 嵌入模型和 YOLOv8n 视觉检测模型，构成端侧 AI 三件套。

模型用途格式参数量内存占用推理引擎
Phi-3-mini-4k-instructRAG 文本生成（问答、规程检索）GGUF Q43.8B~2GBllama-cpp-python (CPU, ARM NEON)
BGE-small-zh文本向量化（知识库嵌入）ONNX33M~130MBONNX Runtime
YOLOv8n-railway铁路缺陷视觉检测（8类）ONNX3.2M~12MBONNX Runtime

选型理由

Phi-3-mini Q4

微软出品，3.8B 参数在 Q4 量化后仅需 ~2GB 内存，CM4 的 4GB RAM 可承受；4096 tokens 上下文窗口足以处理铁路巡检规程问答；llama-cpp-python 在 ARM Cortex-A72 上有 NEON 指令集优化，4 线程推理 2-5 秒/次。

BGE-small-zh

中文语义检索效果优于同级英文模型，ONNX 格式推理速度快，768 维向量兼容 Qdrant 向量数据库。

YOLOv8n

nano 版本适合嵌入式，320x320 输入在 CM4 上推理 <500ms，8 类铁路缺陷覆盖裂纹/磨损/螺栓松动/螺栓缺失/扣件板损/道砟异常/植被侵入/异物侵限。

RAG 推理流程

用户语音问题
    │
    ▼
BGE-small-zh 向量化 ──→ Qdrant Top-5 检索 ──→ 组装 RAG Prompt
                                                    │
                                                    ▼
                                         Phi-3-mini Q4 生成
                                         (≤512 tokens, temp=0.3)
                                                    │
                                                    ▼
                                         答案 + 来源 + 置信度
                                         → BLE 回传眼镜显示

二、如何借助更大算力

挎包终端采用 云-边-端三级协同架构，在本地算力不足时可借助更大算力：

│ 大模型    │  │ 知识库    │  │ 模型训练/    │
│ GPT-4 /  │  │ Dify RAG │  │ 热更新注册   │
│ Qwen-72B │  │ (完整版)  │  │ 中心         │
└──────────┘  └──────────┘  └──────────────┘
📦 边缘端 — 挎包终端 (CM4, 本地推理)

👓 端侧 — 智能眼镜 (ESP32-S3)
显示 + 语音交互 + 拍照触发

算力增强机制

1. 云端大模型回退

当 5G 网络可用时，挎包终端可将复杂查询转发到云端 SaaS 后端，调用 GPT-4 / Qwen-72B 等更大模型。本地 Phi-3 生成置信度 < 0.4 时自动转云端。

2. 知识库增量同步

SaaS 后端维护完整知识库（Dify RAG），挎包终端每小时同步增量。新的铁路规程、作业指导书、故障案例自动下载到本地 Qdrant。

3. YOLO 模型热更新

模型管理器每 5 分钟检查注册中心，下载新版本 YOLO 模型。SHA-256 校验 + 版本号比对，支持一键回滚。

4. 云端协同推理

高复杂度场景（如多目标关联分析）：挎包端 YOLOv8n 初筛 → 发现疑似缺陷 → 上传云端 YOLOv8x/GPT-4V 精检 → 结果回传缓存。

WAL 模式

支持并发读写，巡检过程中不阻塞数据写入。

外键约束

保证数据完整性，设备-照片-检测-告警关联一致。

同步优先级

告警(0) > 照片(1) > 检测(2) > RAG(3) > 遥测(4)，保证关键数据优先上传。

文件存储管理

  • 原子写入：先写 .tmp 文件 → fsync → rename，防止断电损坏
  • 目录组织：按日期 + 巡检 ID 组织，便于检索和清理
  • 磁盘监控：实时检测使用率，90% 触发清理，95% 标记为满
  • LRU 清理：按最近最少使用策略自动删除旧文件
  • SHA-256 校验：每个文件计算哈希，保证完整性

1. 物理隔离 — USB 有线通道

USB 数据导出通道与 5G 网络接口 物理隔离，通过 iptables 防火墙规则实现：

iptables 规则作用
FORWARD -i usb0 -j DROP禁止 USB 接口向其他接口转发
FORWARD -o usb0 -j DROP禁止其他接口向 USB 接口转发
INPUT -i usb0 -j ACCEPT允许 USB 接口本地入站
OUTPUT -o usb0 -j ACCEPT允许 USB 接口本地出站
nat POSTROUTING -o usb0 -j DROP禁止 NAT 伪装通过 USB
OUTPUT -o usb0 --dport 53 -j DROP禁止 DNS 泄漏

关键点：USB 网卡 IP 固定为 10.0.0.1/24，PC 端获得 10.0.0.2，这是一个 封闭局域网，不路由到任何外部网络。

2. 两种数据导出方式

方式 A：PC 专业应用直连 API

PC 通过 USB 数据线连接挎包后，在 PC 端专业应用中通过 HTTP API 访问数据：

PC 专业应用
  → http://10.0.0.1:9090
  → FastAPI (仅绑定 USB 网卡)

方式 B：挎包端打包导出文件

挎包终端可将数据打包为 .tar.gz 文件，供 PC 通过 USB 拷贝传输：

挎包端: 打包 → manifest.json
  + 签名 → .tar.gz
PC 端: USB 挂载 → 拷贝
  → 专业应用导入验证

4. 5G 网络通道（独立于 USB）

5G 接口仅用于与 SaaS 后端同步，与 USB 数据通道完全隔离：

  • 5G 通道：巡检结果上传、知识库同步、模型热更新、告警上报
  • USB 通道：本地数据导出、PC 对接、调试
  • 两个通道通过 iptables 规则互相 DROP，确保数据不会从 USB 通道泄漏到外部网络
