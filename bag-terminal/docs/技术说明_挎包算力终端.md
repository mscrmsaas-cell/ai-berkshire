# 移动智能算力终端节点（挎包）技术说明

## 一、大模型选型

挎包终端采用 **Microsoft Phi-3-mini-4k-instruct (Q4 量化 GGUF)** 作为核心大语言模型，配合 **BGE-small-zh** 嵌入模型和 **YOLOv8n** 视觉检测模型，构成端侧 AI 三件套。

| 模型 | 用途 | 格式 | 参数量 | 内存占用 | 推理引擎 |
|------|------|------|--------|----------|----------|
| Phi-3-mini-4k-instruct | RAG 文本生成（问答、规程检索） | GGUF Q4 | 3.8B | ~2GB | llama-cpp-python (CPU, ARM NEON) |
| BGE-small-zh | 文本向量化（知识库嵌入） | ONNX | 33M | ~130MB | ONNX Runtime |
| YOLOv8n-railway | 铁路缺陷视觉检测（8类） | ONNX | 3.2M | ~12MB | ONNX Runtime |

### 选型理由

- **Phi-3-mini Q4**：微软出品，3.8B 参数在 Q4 量化后仅需 ~2GB 内存，CM4 的 4GB RAM 可承受；4096 tokens 上下文窗口足以处理铁路巡检规程问答；llama-cpp-python 在 ARM Cortex-A72 上有 NEON 指令集优化，4 线程推理 2-5 秒/次
- **BGE-small-zh**：中文语义检索效果优于同级英文模型，ONNX 格式推理速度快，768 维向量兼容 Qdrant
- **YOLOv8n**：nano 版本适合嵌入式，320x320 输入在 CM4 上推理 <500ms，8 类铁路缺陷（裂纹/磨损/螺栓松动/螺栓缺失/扣件板损/道砟异常/植被侵入/异物侵限）

### 推理流程

```
用户语音问题
    │
    ▼
BGE-small-zh 向量化 ──→ Qdrant Top-5 检索 ──→ 组装 RAG Prompt
                                                    │
                                                    ▼
                                         Phi-3-mini Q4 生成
                                         (≤512 tokens, temp=0.3)
                                                    │
                                                    ▼
                                         答案 + 来源 + 置信度
                                         → BLE 回传眼镜显示
```

## 二、如何借助更大算力

挎包终端采用 **云-边-端三级协同架构**，在本地算力不足时可借助更大算力：

### 架构层级

```
┌─────────────────────────────────────────────────────────────────┐
│                      云端 (SaaS + GPU)                          │
│  ┌──────────┐  ┌──────────┐  ┌──────────────┐                  │
│  │ 大模型    │  │ 知识库    │  │ 模型训练/    │                  │
│  │ GPT-4 /  │  │ Dify RAG │  │ 热更新注册   │                  │
│  │ Qwen-72B │  │ (完整版)  │  │ 中心         │                  │
│  └────┬─────┘  └────┬─────┘  └──────┬───────┘                  │
│       │              │               │                          │
└───────┼──────────────┼───────────────┼──────────────────────────┘
        │ 5G/WiFi      │ 5G/WiFi       │ 5G/WiFi
        ▼              ▼               ▼
┌─────────────────────────────────────────────────────────────────┐
│              边缘端 — 挎包终端 (CM4, 本地推理)                   │
│  ┌──────────┐  ┌──────────┐  ┌──────────────┐                  │
│  │ Phi-3    │  │ Qdrant   │  │ YOLOv8n      │                  │
│  │ mini Q4  │  │ (本地)   │  │ (本地)       │                  │
│  └──────────┘  └──────────┘  └──────────────┘                  │
│  降级策略: 网络可用时 → 云端大模型; 网络不可用 → 本地 Phi-3     │
└───────┬─────────────────────────────────────────────────────────┘
        │ BLE NUS
        ▼
┌─────────────────────────────────────────────────────────────────┐
│              端侧 — 智能眼镜 (ESP32-S3)                           │
│  显示 + 语音交互 + 拍照触发                                      │
└─────────────────────────────────────────────────────────────────┘
```

### 算力增强机制

#### 1. 云端大模型回退

当 5G 网络可用时，挎包终端可将复杂查询转发到云端 SaaS 后端，调用 GPT-4 / Qwen-72B 等更大模型：

- **判断逻辑**：本地 Phi-3 生成置信度 < 0.4 时，自动转云端
- **传输方式**：5G 模组 → SaaS API → 大模型推理 → 结果回传
- **降级链路**：云端大模型 → 本地 Phi-3 → 本地知识检索原文

#### 2. 知识库增量同步

SaaS 后端维护完整知识库（Dify RAG），挎包终端定期同步增量：

- **同步间隔**：每小时一次（可配置）
- **同步内容**：新的铁路规程、作业指导书、故障案例
- **传输方式**：SaaS API → BGE 向量化 → Qdrant 本地插入

#### 3. YOLO 模型热更新

模型管理器定期检查注册中心，下载新版本 YOLO 模型：

- **检查间隔**：每 5 分钟
- **验证方式**：SHA-256 校验 + 版本号比对
- **回滚机制**：保留历史版本，新版本异常时一键回滚

#### 4. 云端协同推理

对于高复杂度场景（如多目标关联分析），可将图片上传到云端进行 GPU 推理：

- 挎包端 YOLOv8n 做初筛 → 发现疑似缺陷 → 上传云端 YOLOv8x/GPT-4V 精检
- 云端推理结果写入 SaaS 数据库 → 下发到挎包端缓存

## 三、与眼镜的交互方式

挎包终端通过 **BLE NUS (Nordic UART Service)** 协议与智能眼镜通信，支持最多 4 副眼镜并发连接。

### 通信架构

```
┌──────────────────┐                    ┌──────────────────────────┐
│   智能眼镜        │                    │   挎包终端 (BleBridge)    │
│   (ESP32-S3)     │                    │   (CM4, Central 角色)     │
│                  │   BLE NUS          │                          │
│  ┌────────────┐  │   Service:         │  ┌────────────────────┐  │
│  │ NUS Server │◄─┼──6e400001-...─────┼─►│ NusClient #1~4    │  │
│  │ (Peripheral)│  │   TX: 6e400003    │  │ (自动扫描+连接)    │  │
│  └────────────┘  │   RX: 6e400002    │  └────────┬───────────┘  │
│                  │                    │           │              │
│  消息类型:       │   MTU: 247 bytes   │  消息分发 → AI推理/RAG  │
│  - 心跳          │◄──────────────────►│  - 帧分片重组          │
│  - 拍照请求      │   ACK + 重传       │  - ACK 确认             │
│  - 图像数据      │                    │  - 指数退避重连         │
│  - 语音查询      │                    │                        │
│  - 检测结果      │                    │  → SQLite 缓存         │
│  - 告警          │                    │  → 文件存储             │
│  - 巡检控制      │                    │                        │
└──────────────────┘                    └──────────────────────────┘
```

### 消息协议

BLE 帧格式（最大 payload 4096 字节，支持分片重组）：

| 字段 | 长度 | 说明 |
|------|------|------|
| Magic | 2B | 0x5A 0xA5（帧头标识） |
| MsgType | 1B | 消息类型枚举（心跳/拍照/图像/查询/告警等） |
| SeqNum | 2B | 序列号（ACK 配对） |
| Flags | 1B | 分片标志位 |
| PayloadLen | 2B | payload 长度 |
| Payload | 0~4096B | 实际数据 |
| CRC16 | 2B | CRC-CCITT 校验 |

### 消息类型与交互流程

| 消息类型 | 方向 | 说明 |
|----------|------|------|
| HEARTBEAT (0x01) | 眼镜→挎包 | 心跳，含电量/温度 |
| DEVICE_STATUS_REPORT (0x02) | 眼镜→挎包 | 设备状态上报 |
| CAMERA_ATTACHED/DETACHED (0x10/0x11) | 眼镜→挎包 | 磁吸摄像头连接/断开 |
| CAPTURE_PHOTO_REQ (0x20) | 挎包→眼镜 | 触发拍照 |
| CAMERA_FRAME_DATA (0x21) | 眼镜→挎包 | 图像数据（分片传输） |
| VOICE_QUERY (0x30) | 眼镜→挎包 | 语音问题文本 |
| RAG_ANSWER (0x31) | 挎包→眼镜 | RAG 回答文本（显示+TTS） |
| DETECTION_RESULT (0x40) | 挎包→眼镜 | YOLO 检测结果 |
| ALERT (0x50) | 挎包→眼镜 | 告警通知 |
| INSPECTION_START/END (0x60/0x61) | 挎包→眼镜 | 巡检任务控制 |

### 典型交互流程

**拍照 + AI 检测流程：**
```
眼镜端:  语音"拍照" → 发送 CAPTURE_PHOTO_REQ
挎包端:  接收 → 触发 ESP32 拍照 → 接收 CAMERA_FRAME_DATA (分片)
         → YOLOv8n 推理 → 缓存到 SQLite + 存储图片到 SD 卡
         → 返回 DETECTION_RESULT (缺陷类型+位置+置信度)
眼镜端:  OLED 显示检测结果 → 语音播报
```

**语音问答流程：**
```
眼镜端:  语音识别 → 发送 VOICE_QUERY (文本)
挎包端:  BGE 向量化 → Qdrant 检索 Top-5 → Phi-3 生成
         → 返回 RAG_ANSWER (答案+来源)
眼镜端:  OLED 显示答案 → TTS 播报
```

## 四、数据存储方案

挎包终端采用 **三层存储架构**：SQLite（结构化数据）+ 文件系统（媒体文件）+ Qdrant（向量数据）。

### 存储架构

```
/mnt/sdcard/bag-terminal/
├── data/
│   ├── bag_terminal.db          ← SQLite 数据库 (8 张表)
│   └── qdrant/                  ← Qdrant 向量数据库 (本地模式)
├── photos/
│   └── 2026-01-15/
│       └── insp_{巡检ID}/
│           ├── 20260115_103022_glass01_0001.jpg
│           └── 20260115_103055_glass01_0002.jpg
├── videos/
│   └── 2026-01-15/
│       └── insp_{巡检ID}/
│           └── 20260115_103022_glass01_0001.h264
├── alerts/
│   └── 2026-01-15/
│       └── alert_{告警ID}.jpg
├── exports/                    ← 数据导出包 (USB 对接)
├── logs/
└── models/                     ← AI 模型文件
    ├── yolo/
    │   ├── yolov8n_railway.onnx
    │   └── yolov8n_railway_v1.1.0.onnx
    ├── embedding/
    │   └── bge-small-zh.onnx
    ├── llm/
    │   └── phi-3-mini-4k-instruct-q4.gguf
    └── manifest.json           ← 模型版本清单
```

### SQLite 数据库（8 张表）

| 表名 | 用途 | 关键字段 |
|------|------|----------|
| glasses_devices | 眼镜设备注册 | tuya_device_id, ble_address, firmware_version, battery_level |
| camera_module_events | 摄像头连接记录 | device_id, event_type, connected_at, frame_count |
| inspection_tasks | 巡检任务缓存 | id, project_id, inspector_id, status, ai_findings |
| inspection_photos_cache | 照片缓存 | inspection_id, local_path, upload_status, minio_object_name |
| ai_detection_cache | AI 检测结果 | photo_id, model_name, model_version, detection_json |
| rag_query_cache | RAG 问答缓存 | question, answer, sources, confidence, from_local |
| alerts_cache | 告警缓存 | alert_type, severity, sync_priority, sync_status |
| sync_state | 同步状态追踪 | table_name, record_id, sync_direction, sync_priority |

- **WAL 模式**：支持并发读写，巡检过程中不阻塞
- **外键约束**：保证数据完整性
- **同步优先级**：告警(0) > 照片(1) > 检测(2) > RAG(3) > 遥测(4)

### 文件存储管理

- **原子写入**：先写 `.tmp` 文件 → `fsync` → `rename`，防止断电损坏
- **目录组织**：按日期 + 巡检 ID 组织，便于检索和清理
- **磁盘监控**：实时检测使用率，90% 触发清理，95% 标记为满
- **LRU 清理**：按最近最少使用策略自动删除旧文件
- **SHA-256 校验**：每个文件计算哈希，保证完整性

### Qdrant 向量数据库

- **本地模式**：嵌入式运行，无需独立服务
- **集合**：`railway_knowledge`，768 维
- **增量同步**：每小时从 SaaS Dify RAG 同步新文档
- **检索**：Top-5，余弦相似度阈值 0.5

## 五、数据与外部的安全隔离

这是整个系统的核心安全设计，采用 **物理隔离 + 逻辑隔离 + 加密验证** 三重保障。

### 安全隔离总览

```
┌──────────────────────────────────────────────────────────────────┐
│                        挎包终端 (CM4)                             │
│                                                                  │
│  ┌─────────────┐          ┌──────────────────┐                 │
│  │  内部数据区  │          │  USB 导出通道     │                 │
│  │             │          │  (物理隔离)       │                 │
│  │ • SQLite DB │          │                  │                 │
│  │ • 照片/视频  │  数据线   │  USB 网卡 usb0   │   USB 线缆      │
│  │ • AI 模型   │  连接PC   │  IP: 10.0.0.1    │◄──────────────► │
│  │ • Qdrant    │ ────────► │  FastAPI :9090   │               PC │
│  │ • 告警数据   │          │  Token 认证       │               端 │
│  │             │          │                  │               专 │
│  │  ❌ 不可直接 │          │  CDC-ACM 串口     │               业 │
│  │    对外传输  │          │  /dev/ttyACM0    │               应 │
│  │             │          │  调试白名单       │               用 │
│  └─────────────┘          └──────────────────┘                 │
│         │                           │                          │
│         │      iptables 防火墙        │                          │
│         │  ┌──────────────────────┐  │                          │
│         └──┤ FORWARD: DROP (双向)  ├──┘                          │
│            │ NAT: DROP            │                              │
│            │ DNS: DROP            │                              │
│            └──────────────────────┘                              │
│                                  │                              │
│  ┌──────────────────┐            │                              │
│  │  5G 网络接口      │◄───────────┘                              │
│  │  (独立于USB通道)  │  ← iptables 禁止 USB↔5G 转发             │
│  │  仅用于 SaaS 同步  │                                           │
│  └──────────────────┘                                           │
└──────────────────────────────────────────────────────────────────┘
```

### 1. 物理隔离 — USB 有线通道

USB 数据导出通道与 5G 网络接口 **物理隔离**，通过 iptables 防火墙规则实现：

| 规则 | 作用 |
|------|------|
| `FORWARD -i usb0 -j DROP` | 禁止 USB 接口向其他接口转发 |
| `FORWARD -o usb0 -j DROP` | 禁止其他接口向 USB 接口转发 |
| `INPUT -i usb0 -j ACCEPT` | 允许 USB 接口本地入站 |
| `OUTPUT -o usb0 -j ACCEPT` | 允许 USB 接口本地出站 |
| `nat POSTROUTING -o usb0 -j DROP` | 禁止 NAT 伪装通过 USB |
| `OUTPUT -o usb0 --dport 53 -j DROP` | 禁止 DNS 泄漏 |

**关键点**：USB 网卡 IP 固定为 `10.0.0.1/24`，PC 端获得 `10.0.0.2`，这是一个 **封闭局域网**，不路由到任何外部网络。

### 2. 两种数据导出方式

#### 方式 A：PC 端专业应用直连 API

PC 通过 USB 数据线连接挎包后，在 PC 端专业应用中通过 HTTP API 访问数据：

```
PC 专业应用 → http://10.0.0.1:9090 → FastAPI (仅绑定 USB 网卡)
```

**API 接口清单：**

| 端点 | 方法 | 说明 |
|------|------|------|
| `/auth/pair` | POST | 获取认证 Token（USB 连接时自动生成） |
| `/exports/create` | POST | 创建数据导出包 |
| `/exports/{id}/download` | GET | 下载导出包 |
| `/exports/{id}/verify` | GET | 验证导出包完整性 |
| `/photos/list` | GET | 列出照片 |
| `/photos/{id}/download` | GET | 下载单张照片 |
| `/detections/list` | GET | 列出检测结果 |
| `/alerts/list` | GET | 列出告警 |
| `/rag/queries` | GET | 列出 RAG 问答记录 |
| `/tasks/list` | GET | 列出巡检任务 |
| `/health` | GET | 健康检查 |

**认证流程：**
1. USB 连接时，挎包自动生成 8 位数字 Token（TTL 30 分钟）
2. Token 显示在挎包 OLED 屏上
3. PC 端用户在专业应用中输入 Token
4. 后续请求携带 `X-Auth-Token` Header
5. USB 断开时 Token 自动撤销

#### 方式 B：挎包端打包导出文件

挎包终端可将数据打包为 `.tar.gz` 文件，供 PC 通过 USB 拷贝传输：

```
挎包端: 打包数据 → manifest.json + 签名 → .tar.gz → /mnt/sdcard/exports/
PC 端: USB 挂载 → 拷贝 .tar.gz → 专业应用导入验证
```

**导出包结构：**
```
export_20260115_103022_photos.tar.gz
├── manifest.json           ← 清单 (导出ID/类型/文件列表/SHA-256)
├── signature.sha256        ← HMAC-SHA256 签名
├── photos/
│   ├── 20260115_103022_glass01_0001.jpg
│   └── ...
├── detections.json         ← AI 检测结果
├── alerts.json             ← 告警记录
└── metadata.json           ← 巡检元数据
```

**完整性验证：**
- 每个文件计算 SHA-256 哈希，写入 manifest.json
- 整个 manifest.json 用 HMAC-SHA256 签名
- PC 端专业应用导入时验证签名 + 逐文件校验哈希
- 密钥通过环境变量 `BAG_EXPORT_HMAC_KEY` 注入，生产环境必须修改

### 3. 串口调试接口（预留）

CDC-ACM 串口 (`/dev/ttyACM0`) 提供受限调试通道：

| 特性 | 说明 |
|------|------|
| 认证 | 需 Token 认证（与 API 共享） |
| Shell 白名单 | ls, df, free, uptime, dmesg, ip, ps, cat, grep, sqlite3, python3 |
| 命令超时 | 10 秒 |
| 速率限制 | 10 命令/秒 |
| 日志审计 | 所有命令记录到日志 |

**调试命令示例：**
```
> auth 12345678          ← Token 认证
> status                 ← 系统状态
> shell df -h            ← 查看磁盘
> shell sqlite3 /app/data/bag_terminal.db "SELECT COUNT(*) FROM alerts_cache"
> export create --type photos --date 2026-01-15
> logs tail 50           ← 查看最近日志
```

### 4. 5G 网络通道（独立于 USB）

5G 接口仅用于与 SaaS 后端同步，与 USB 数据通道完全隔离：

- 5G 通道：巡检结果上传、知识库同步、模型热更新、告警上报
- USB 通道：本地数据导出、PC 对接、调试
- 两个通道通过 iptables 规则互相 DROP，确保数据不会从 USB 通道泄漏到外部网络

### 安全设计总结

| 层级 | 机制 | 实现 |
|------|------|------|
| 物理层 | USB 有线连接 | 仅物理数据线可触发导出 |
| 网络层 | iptables 防火墙 | USB↔5G 双向 DROP |
